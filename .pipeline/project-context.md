## 2. DocTypes

### Module: Petty Cash

#### Petty Cash Sheet  (parent — `is_submittable: 1`)
`vcl_finance/petty_cash/doctype/petty_cash_sheet/petty_cash_sheet.json`
Controller: `…/petty_cash_sheet.py` (the only substantial controller in the app).
- `autoname: naming_series:`, series `PCS-.YYYY.-` (naming_rule "By Naming Series field"); `title_field: week_ending`.
- Key fields: `week_no` (Int, read-only, ISO week), `week_ending` (Date, **unique**, must be a Friday), `custodian` (Link→Employee), `custodian_name` (Data, default "Shiro"), `opening_balance`, `closing_balance` (computed = expected_close), `cash_count_end`, `authorised_float` (default 50000), computed `total_out`/`total_in`/`expected_close`/`variance`, `status` (Select Draft/Submitted/Approved), `amended_from`, `notes` (Text Editor).
- **Child tables (Table fields → child doctype):**
  - `vouchers` → **Petty Cash Voucher**
  - `parking_entries` → **Petty Cash Parking Entry**
  - `misc_entries` → **Petty Cash Misc Entry**
  - `wages_entries` → **Petty Cash Wages Entry**
- Permissions: System Manager (full), Accounts Manager (full incl. submit/cancel, no delete), Accounts User (create/read/write/print, **no submit**).
- Controller behaviour (`petty_cash_sheet.py`):
  - `validate()` → `validate_week_ending()` (throws unless `weekday()==4`), `derive_week_no()` (ISO week), `ensure_grid()`, `compute_totals()`.
  - `before_save()` mirrors `closing_balance = expected_close`.
  - `on_submit()` sets status "Submitted"; `on_cancel()` resets to "Draft".
  - `ensure_grid()` (`:74`) idempotently back-fills empty child rows so the editor renders a fixed grid: 18 vouchers, 6 days×5 vehicles×2 slots parking, 6 bike + 4 forklift misc, 18 wages. **Skips when `docstatus==1`** (frozen after submit).
  - `compute_totals()` (`:127`): voucher OUT = sum of amt_tg/te/se/oa/cm/ot across rows; `total_out = voucher_out + parking + misc + wages`; `total_in = Σ amt_in`; `expected_close = opening − total_out + total_in`; `variance = cash_count_end − expected_close`.
  - **Whitelisted API methods** (module-level): `week_dates(week_ending)`, `summary(name)` (server-recomputed totals/counts for the live editor), `create_for_week(week_ending, custodian_name="Shiro", opening_balance, authorised_float)` (idempotent on week_ending; used by the `www/petty-cash/new` form).
  - Module constants reused by www pages: `VEHICLES` (5 plates), `DAY_NAMES` (Mon–Sat), `VOUCHER_ROWS=18`, `WAGES_ROWS=18`, `BIKE_ROWS=6`, `FORKLIFT_ROWS=4`.

#### Petty Cash Voucher  (child — `istable: 1`)
`…/petty_cash_voucher/petty_cash_voucher.json`; controller is a `pass` stub.
- Fields: `row_idx` (Int read-only), `txn_date`, `voucher_no`, `recipient`, `amt_tg`/`amt_te`/`amt_se`/`amt_oa`/`amt_cm`/`amt_ot` (Currency non_negative, per-category OUT), `amt_in` (Currency, cash refund), `pc_received`/`etr_received` (Check), `notes` (Small Text).
- NOTE: category set here is **TG/TE/SE/OA/CM/OT** (six). No `amt_fd`/`amt_gp`, and `cm` is present as a voucher column (prototype dropped CM from vouchers — see §5 gaps). No receipt/attach field.

#### Petty Cash Parking Entry (child — `istable`)
Fields: `day_idx` (Select Mon..Sat — **string**, not int), `vehicle` (Select of 5 plates), `slot` (Int 1/2), `amount` (Currency).

#### Petty Cash Misc Entry (child — `istable`)
Fields: `kind` (Select **"Bike Fuel" / "Forklift"** — note the human labels), `row_idx`, `txn_date`, `amount`, `recipient_signed` (Check), `notes`.

#### Petty Cash Wages Entry (child — `istable`)
Fields: `row_idx`, `txn_date`, `entry_type` (Select **Wage / Loan** only), `recipient`, `staff_id`, `reason`, `amount`, `paye` (Check), `recipient_signed`, `authorised_signed`.
- Wages AND loans collapsed into ONE child table here (prototype keeps them as two separate tables — see §5).

#### Petty Cash Category (master)
`…/petty_cash_category/petty_cash_category.json`; controller upper-cases `code` in `validate()`.
- `autoname: field:code`; fields `code` (Data unique, len 8), `label`, `gl_account` (Link→Account, "Phase 3 posting"), `disabled`.
- Seeded by `install.py` → TG, TE, SE, OA, CM, OT (`after_install`, idempotent).

### Module: AR Reconciliation  (independent; thin sync controllers)

- **AR Customer Recon** (`autoname: field:canonical_customer`, master). Per-customer summary: `true_open`, `qbo_stated`, `variance`, four continuity joints `jN_pass`/`jN_gap`, reliability/pattern fields, lake/erp sync timestamps. `before_save()` sets `variance = qbo_stated − true_open`. (Note: label says "QBO − True"; code matches.)
- **AR Open Entry** (`autoname: hash`). Open allocatable item; `canonical_customer` is **Link→AR Customer Recon**; `sync_key` (Data unique = `canonical|entry_ref|side`), `side` Debit/Credit, `source` hist/qbo. Controller `pass`.
- **AR Allocation** (`autoname: hash`). Credit↔debit allocation; `sync_key` unique = `canonical|alloc_id`; `match_method`, `confidence`, `origin` (lake/manual/erp). `before_save()` stamps `updated_at`, defaults `origin="lake"`, and flips `origin="manual"` on a non-sync user edit of amount/refs (guarded by `self.flags.from_lake_sync`).

**Parent↔child summary:** only Petty Cash Sheet owns child tables (the 4 above). AR doctypes are flat and linked by `canonical_customer`/`sync_key`, NOT Frappe child tables.

## 3. Frappe conventions in THIS repo (`hooks.py`)

`vcl_finance/hooks.py` is intentionally minimal:
- `app_include_css/js` and `web_include_css/js` → `/assets/vcl_finance/css/petty_cash.css` and `…/js/petty_cash.js` (loaded in Desk AND on website pages).
- `after_install = "vcl_finance.petty_cash.install.after_install"` — seeds the 6 categories.
- **NOT wired (all absent):** `doc_events`, `scheduler_events`, `fixtures`, `override_whitelisted_methods`, `website_route_rules`, `permission_query_conditions`, `has_permission`, `notification_config`, custom `boot`. A Coder adding any of these is introducing a new pattern.
- `patches.txt` is empty (no data migrations yet). `config/desktop.py` provides the Desk workspace tile.

**Website pages** (`www/petty-cash/`, served at `/petty-cash/*`; each `.py` exposes `get_context`):
- `index.py` + `index.html` → `/petty-cash/` list of sheets (guards Guest; reads via `frappe.get_all`).
- `new.py` + `new.html` → `/petty-cash/new`; on POST calls `create_for_week(...)` then `raise frappe.Redirect` to the sheet editor.
- `sheet.py` + `sheet.html` → `/petty-cash/sheet?name=PCS-…`; the editor. Force-fills the grid once on first render (`ensure_grid()` + `save(ignore_permissions=True)`). Builds `parking_grid[day][vehicle][slot]`, sorted bike/forklift rows, week dates.
- `print.py` + `print.html` → `/petty-cash/print?name=…&copies=1..4`; A4-landscape blank/filled print; chunks vouchers into 18-row pages; recomputes the category/parking/wages/loans summary server-side.
- All four guard `frappe.session.user == "Guest"` and use `frappe.has_permission("Petty Cash Sheet", "read", name)`.
- `sheet.html` injects `<meta name="csrf_token">` and `data-pc-editor="1" data-pc-sheet="{{doc.name}}"` to activate the JS.

**Client JS** (`public/js/petty_cash.js`): activates only when `document.body.dataset.pcEditor` is set. Autosaves via Frappe **REST** `PUT /api/resource/Petty Cash Sheet/<name>` (child-row patch sends `{table:[{name, ...fields}]}`; parent patch sends top-level fields). Sends `X-Frappe-CSRF-Token` + `X-Requested-With`. Live totals come from the whitelisted `summary` method, NOT client math. (This is a www-portal pattern; there is **no Desk form `.js` client script** for any doctype in this repo.)

## 4. Server-side patterns

- **Validation style:** lifecycle methods on the Document subclass (`validate`/`before_save`/`on_submit`/`on_cancel`); `frappe.throw(_(...))` for user errors. Dates normalised via a local `_as_date()` helper (handles date/datetime/iso-string) in `petty_cash_sheet.py:200`.
- **Money/rounding:** Currency fields with `"options": "currency"` and `non_negative: 1`; totals computed in plain Python floats then assigned to Currency fields (Frappe rounds on store). No `flt(...)`/precision calls yet — a Coder adding posting should use `frappe.utils.flt(x, 2)` to be safe. Amounts default `"0"`.
- **Whitelisted API:** `@frappe.whitelist()` module-level functions in the controller (see §2). They re-fetch the doc and recompute server-side (never trust client). Pattern to follow for new endpoints (quick-entry, feed, receipt upload per the migration plan).
- **Party/account linking:** `custodian`→Employee, `category.gl_account`→Account exist but are **unused** so far. No ERPNext financial docs (Journal Entry / Payment Entry) are created anywhere in `vcl_finance` yet — posting is Phase-2 future work (the prototype's `posting.py` is the reference, see §5).
- **AR sync pattern:** `before_save` stamps `updated_at`/`variance`, uses `self.flags` + `self.has_value_changed(...)` to distinguish lake-sync writes from manual edits (last-write-wins / origin tracking).

## 7. Conventions a code generator MUST preserve

- **DocType JSON shape:** keep the existing key set (`actions`, `field_order`, `fields`, `permissions`, `links`, `states`, `modified`, `module`, `name`, sort fields). Each DocType lives in its own folder `…/doctype/<snake_name>/` with `<snake>.json`, `<snake>.py`, `__init__.py` (and optional `<snake>.js`). The folder/file names are **snake_case of the DocType name**; the controller class is **PascalCase with NO spaces** (e.g. `PettyCashSheet`, `ARCustomerRecon`).
- **`module` in every DocType JSON** must be exactly `"Petty Cash"` or `"AR Reconciliation"` — and those exact strings must stay in `modules.txt` (folder = snake_case `petty_cash` / `ar_reconciliation`). Adding a DocType under a new module means adding the line to `modules.txt`.
- **Field-name casing is load-bearing:** the www templates, `print.py`, `summary()`, `compute_totals()`, and `public/js/petty_cash.js` all reference `amt_tg…amt_ot`, `amt_in`, `entry_type`, `kind` ("Bike Fuel"/"Forklift"), `day_idx` (Mon..Sat strings), `slot`, `row_idx`. Renaming any breaks the editor/print silently. If you ADD `amt_fd`/`amt_gp`, update **all** of `compute_totals()`, `summary()`, `print.py`, the templates, and the JS.
- **Grid invariants:** `ensure_grid()` row counts (18/parking-grid/6+4/18) are mirrored by the templates' fixed rows and by `print.py` chunking on `VOUCHER_ROWS`. Change one → change all.
- **Submittable freeze:** never back-fill or mutate child rows when `docstatus==1` (`ensure_grid` guards this). Status strings are exactly `Draft/Submitted/Approved`.
- **Naming series** `PCS-.YYYY.-` and `week_ending` Friday+unique rule are user-visible contracts; the `summary`/`create_for_week`/`week_dates` whitelisted names are called by templates/JS — don't rename without updating callers.
- **No money via raw client values** — recompute server-side (follow `summary()`); use `frappe.utils.flt(x, 2)` for any new money math.
- **Posting must be DRAFT only:** per VCL convention, any Journal Entry the posting layer creates is a **Draft** for human review — never auto-submit (matches the prototype's draft-JE behaviour and VCL's "leave JEs as drafts" rule).

## Gotchas / do-not-break

1. **`week_ending` is globally unique** — blocks the two-float (Cash/Hauz-Pay) model from the prototype. Float support needs a new field + composite uniqueness, not a second sheet on the same Friday.
2. **Voucher categories diverge from the prototype**: repo has CM (in vouchers) but lacks FD/GP; prototype moved CM→wages and added Food/Geeprint. Reconcile before backfill.
3. **Wages + Loans are one table here, two in the prototype** — and the loan `amount_issued` vs `amount_signed` distinction (only issued cash leaves the float) is **lost**; the current single `amount` field can't represent it.
4. **Enum value drift**: `misc.kind` = "Bike Fuel"/"Forklift" (vs proto `bike`/`forklift`); `parking.day_idx` = "Mon".."Sat" strings (vs proto int 0–5); `wages.entry_type` only Wage/Loan (vs proto W/O/P/C/L). Any importer/backfill must translate.
5. **`ensure_grid()` must skip submitted docs** (`docstatus==1`) or it corrupts frozen sheets. Keep the guard.
6. **No Desk client scripts** — all editor logic is `public/js/petty_cash.js`, gated on `data-pc-editor`, talking to REST + the whitelisted `summary`. Adding Desk-side JS is a new pattern; prefer reusing the whitelisted methods.
7. **No JE/posting code exists yet** — `category.gl_account` is the only hook. The prototype `posting.py` (official→ERP COA crosswalk, M-Pesa/bank-charge parking, additive `src_key` rebuild) is the spec; JEs must be Draft.
8. **`patches.txt` is empty** — any data backfill (decision #2) needs a new patch module + line; remember enum/category translation (gotchas 2–4).
9. **No tests in repo** and **no local bench** — tests must be Frappe `FrappeTestCase` under the doctype folder and run via `bench --site <site> run-tests --app vcl_finance`; the Stage-0 agent cannot execute them here.
10. **AR Reconciliation is a separate workstream** sharing the app — don't entangle its lake-sync `origin`/`sync_key` logic with petty-cash changes.
